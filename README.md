This provided practical exposure to:

**Security mindset**

Instead of asking only:

> "Does the application work?"

I started asking:

> "What is exposed?"
> "Who can reach it?"
> "How is access authenticated?"
> "What happens if a security layer fails?"
> "Where could an attacker move?"
> "How would I detect it?"

*Implementation details are intentionally omitted to respect enterprise confidentiality.*

### 🌐 Network Specialist / Developer Internship
**June 21 – July 21, 2026**

During my internship, I worked as a **Network Specialist / Developer**, splitting my time between troubleshooting network issues and building a secure connectivity project.

**Network troubleshooting**

- Diagnosing and resolving connectivity issues
- Identifying misconfigurations affecting network access
- Supporting the reliability of internal network services

**Project: Secure tunneling with Cloudflare**

- Set up and configured a **Cloudflare Tunnel** to securely expose a service without opening inbound ports on the network
- Connected the internal service to the outside through Cloudflare's edge network
- Focused on reducing attack surface by avoiding direct public exposure of internal infrastructure

**Stack:** ![Cloudflare](https://img.shields.io/badge/Cloudflare-0d1117?style=for-the-badge&logo=cloudflare&logoColor=F38020) ![Networking](https://img.shields.io/badge/Networking-0d1117?style=for-the-badge)

**What it reinforced**

> "Why expose a port when you can tunnel out instead?"

Working with Cloudflare Tunnels shifted how I think about exposure: instead of opening inbound access and defending it, the goal became avoiding inbound exposure entirely.

*Company and internal details are intentionally omitted to respect confidentiality.*
